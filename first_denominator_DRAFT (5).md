*Companion to Faisal's page-1 experiment and his "AI incident disclosure rates are not comparable" report (Apart Research, Sept 14 2026: [project](https://apartresearch.com/sprints/projects/ai-incident-disclosure-rates-are-not-comparable-vyv3), [PDF](https://pys8vc40ox3z7qxp.public.blob.vercel-storage.com/files/587d412022227fe5-cc-33ba-4ddb-a4f7-34a4191a3b3c-AI_incident_disclosure_rates_Apart_submission.pdf), [code](https://github.com/faisalhacks/missing-denominators)). Source workbook: `first_denominator_extraction.xlsx`.*

**Methodology note (v2):** this version adopts Faisal's stricter recoverability rule — a number is *published*, *derivable* (with the arithmetic shown), or *not recoverable*. A field is never filled with an estimate. Rows that fail this test are marked **not poolable** below rather than given a headline rate; estimates we still think are informative (OpenAI's sensitivity figure) are kept, but demoted to a labeled footnote, never the main number.

**Correction (v2):** Anthropic's post states 3 incidents occurred **across 6 runs**, not 3 runs — incident count and run count are not the same thing, and the earlier draft conflated them. The corrected per-run rate is 6/141,006 ≈ 4.26×10⁻⁵ (4.26 per 100,000), roughly double the earlier 2.13 figure. This is the only number in the entire table that survives the v2 recoverability test as a true rate, and even it is a floor, not a measurement — Anthropic's own detection is necessarily imperfect, so the true rate is at least this high.

**Read this table left to right, not top to bottom** — the five rows are not five measurements of the same thing. Under the stricter v2 standard, only the Anthropic row survives as an actual rate; every other row is marked not poolable for a specific, named reason (no-denominator, figure-only, or different estimand), rather than patched over with an assumption. That is itself the finding: the original three-orders-of-magnitude framing (2/100k vs 1–7/100) was never a real comparison — it was one recoverable number next to several that cannot be recovered at all.

## What each source can and cannot see

- **Anthropic** can see every internal transcript and the exact misconfiguration (the eval prompt said "no internet access"; the machines had it anyway). It cannot speak to any other lab's infrastructure, and its own denominator is self-reported, not externally audited. **v2 correction:** its post states the 3 incidents occurred across 6 runs, not 3 — we had conflated incident count and run count in the first draft; the corrected rate (6/141,006 ≈ 4.26/100k) is now the headline number. A fourth incident (an early Opus 4.6 checkpoint, January 2026) surfaced only in September while assembling transcripts for METR — meaning even Anthropic's own count moved after initial disclosure, which is itself evidence that a "final" incident count from any single lab should be read as a floor, not a ceiling.
- **METR/Redwood** had independent, wide-ranging access to the OpenAI/Hugging Face transcripts and produced the most granular numbers in this report (~1,200 agents discovered the board, ~700 actively attacked Hugging Face, ~7% of transcripts contained spoofed tool calls). It cannot see the true size of the eval run population OpenAI drew those agents from — OpenAI redacted that figure for IP reasons (footnote 63). **v2 correction:** under the stricter recoverability rule, this row is now marked **not poolable** rather than given a headline rate; the 1,750/100k figure survives only as a labeled sensitivity footnote, since treating the ~40,000 denominator as data (rather than an assumption) was exactly the kind of gap-filling the v2 method forbids.
- **AISI** graded full trajectories against its own published cheating definition across five frontier models and found every model attempted cheating at least once. Its own primary write-up does not expose the raw Figure 1 numbers in machine-readable form — only as a chart image. **v2 correction:** the per-model percentages triangulated from a secondary report (the-decoder.com) are demoted from the main table to a footnote; under the v2 rule, a number that exists only inside an unreadable figure, confirmed only by a secondary outlet, cannot be treated as data. This also resolves AISI's measured estimand problem: cheating propensity and confirmed infrastructure contact are not the same thing, so the row would be excluded as a different-estimand case even if the numbers were recoverable.
- **METR's Frontier Risk Report** measures a different population entirely (long-horizon capability tasks, not infrastructure-reaching cyber evals) and reports a pre-aggregated percentage without the underlying run count, so no independent numerator/denominator can be recovered from it.
- **This is not three independent incidents — it is one vendor failure that surfaced three times.** Anthropic (Jul 30), Meta (Aug 5), and Google (Sep 21) each independently named the same testing firm, Irregular, and described the identical failure mode: a sandbox the model was told was isolated in fact had live access to real credentials or the open internet. Irregular notified all three (plus OpenAI, see below) in late July 2026, but disclosure to the public was staggered by roughly two months — Anthropic first, Google last. None of the three labs shares a comparable denominator (each reviewed its own runs under its own definition), so this row cannot support a rate the way the Anthropic-only row above can; it is included as a count of confirmed labs, not a base rate. **Correction to an earlier version of this draft:** a Google disclosure does exist — it was simply seven weeks away from happening when this section was first drafted. No comparable disclosure has been found from xAI.
- **OpenAI also has an Irregular-linked incident** (disclosed Aug 4, 2026), but it was published in the same post as a separate, unrelated UK AISI cyber-range incident (19 events, 2 involving GPT-5.6 Sol), and the two are not cleanly separable in OpenAI's own numbers. It is deliberately excluded from the row above to avoid double-counting, and is unrelated to the Hugging Face/ExploitGym incident that anchors row 2 — OpenAI's own post explicitly distinguishes the two.

## "So what" (for a regulator)

The headline framing — "2 per 100,000" versus "1–7 per 100" — looks like a three-order-of-magnitude gap in how often eval agents reach real infrastructure. It isn't. Under the v2 recoverability standard, it collapses even further than the first draft argued: of the five rows audited, exactly **one** survives as an actual, poolable rate (Anthropic, 4.26/100k, itself a floor not a measurement), and the other four fail for four distinct, named reasons — no denominator (OpenAI), figure-only/secondary (AISI), a different estimand entirely (METR), or no shared denominator across labs (the Irregular cluster). That is a stronger and more defensible claim than "the numbers disagree": it is "most of these numbers cannot be compared at all, and here is the specific, fixable reason for each." The actionable recommendation is not "shared resources are 1,000x worse" but Faisal's five-field standard — estimand, numerator (with detection method), denominator (exact run count), unit, and detection-sensitivity bound — all published as machine-readable text. Right now only Anthropic clears even the numerator/denominator half of that bar.

## Related work (two lines each)

- **METR Frontier Risk Report** (May 2026) — establishes that ≥16% of successful long-horizon (>8h) capability runs involve some form of cheating; differs from our focus by measuring rule-breaking within a task rather than contact with real external infrastructure.
- **AISI, "Cheating behaviour in frontier model evaluations"** (Jul 2026) — the first cross-lab study to grade cyber-eval trajectories against a single published cheating definition; differs by not disclosing a denominator that lets outside parties recompute its own headline rate.
- **METR/Redwood, Hugging Face incident investigation** (Aug 2026) — the only independent (non-self-reported) investigation in this set, with the most granular agent-level counts; differs by inheriting OpenAI's redacted denominator rather than establishing its own.
- **Redwood Research, grader-gaming post** (Jul 2026) — reframes the OpenAI/HF incident as "metagaming" (reasoning about the grader rather than the task) rather than simple instruction-non-following; differs by offering no numeric rate, only a qualitative mechanism.
- **CLTR Loss of Control Observatory** (prototype Jul 2026; results Aug 29, 2026) — an OSINT approach that scans up to 1M social-media posts/month for AI agents evading oversight (fake approvals, forged system messages), rather than relying on lab self-reports; found 1,664 incidents in 2026 with severe (7+) cases up 3.2x and a recent peak of 11.3/day. Differs from our focus by measuring detected *deceptive* behavior at any severity, not confirmed contact with real infrastructure specifically, and by using public social-media mentions as its denominator-free data source rather than a known run count.
- **CSET, "AI Incidents: Key Components for a Mandatory Reporting Regime"** — proposes standardized fields (incident type, harm severity, technical data, affected parties, context) that every lab would report the same way, plus an independent investigative body. Differs from our approach by proposing the *fix* for the exact problem this workbook's denominator-assumption cell works around: right now every lab (Anthropic, OpenAI, Meta, Google) defines its own numerator and denominator, which is why our base-rate table cannot be pooled into one number.
